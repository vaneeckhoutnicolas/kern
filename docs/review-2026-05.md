# External review — May 2026 (v1.1-rc)

*A standing record of an independent code/security/legal/use-case review of the
Kern reference implementation at v1.1-rc. Findings are grouped by severity.
Each item is marked **[FIXED]** (changed in the accompanying patch) or
**[RECOMMENDED]** (left for the maintainer to action, often because the change
is a judgement call, an economic decision, or too invasive to make blind).*

This document is informational and is **not legal advice**. See
[`disclaimer.md`](disclaimer.md). The regulatory observations below should be
confirmed with licensed counsel and the competent national authority.

---

## Summary judgement

The project is large and carefully built: ~24k lines of Python, **692 tests
passing** (up from 672 after this review's additions), a sound signature
discipline (pubkey→address identity binding plus `chain_id` anti-replay), real
gas metering in the rollup Mini-EVM, and an unusually thorough disclaimer. The
`use-cases.md` "what Kern is *not* for" section shows mature product judgement.

The central tension to manage is that the repository reads, in places, like a
**reference implementation** and, in other places, like a **launching mainnet
with a 70M public token sale**. The gap between those two is large, and a few
marketing claims out-ran what the code and the law support. The corrections
below close the most important of those gaps.

## Legal

### L1 — Securities vs MiCA scope error · **[FIXED — docs reframed]**

`sto-mica.md` and the three STO templates were framed as
"MiCA-Compliant by Construction." Tokenized **equity, fund units, and
real-estate fund interests are financial instruments under MiFID II**, and
**MiCA Art. 2(4) explicitly excludes financial instruments from MiCA's scope.**
They are governed by the *existing* securities regime — **MiFID II + Prospectus
Regulation + MAR + AIFMD (for funds) + the DLT Pilot Regime** — not MiCA. The
draft also mis-cited "MiCA Art. 88" (crypto market abuse) for what is securities
market abuse (**MAR**) and "MiCA Art. 50" (CASP custody) for what is a securities
issuer's custody duty (**MiFID II Art. 16 / AIFMD Art. 21**).

*Action taken:* the correction is now applied **throughout** the repository, not
just the primary doc: the scope-correction box and retitle in `sto-mica.md`; the
README intro; the whitepaper (`whitepaper.md` and the rendered
`kern_site/whitepaper.html`); the `v11rc-changes.md` changelog; the website
(`index.html`), explorer dashboard (`sto_dashboard.html`), Grafana dashboard and
AlertManager rules; the Prometheus metric (`kern_sto_contracts_mica_compliant` →
`kern_sto_contracts_compliant`) and JSON summary field (`mica_compliant` →
`compliant`); the Skald `is_mica_compliant` view → `is_compliant`; and — most
importantly, because these are the regulator-facing artifacts — the **invariant
identifiers inside the three contracts** (`mica_art14_*` → `prospectus_*`,
`mica_art50_*` → `mifid_art16_*`). All affected tests were updated in lockstep.
*Still required:* the deeper in-line article-by-article prose in `sto-mica.md` §2
remains illustrative pending a counsel review before any template is used for a
real raise. (The file name `sto-mica.md` was kept to avoid breaking inbound links;
its content now opens with the correction.)

### L2 — Missing documentation-license file · **[FIXED]**

Documentation declared itself CC-BY-SA-4.0, but no such license file existed and
`disclaimer.md` / `legal-audit.md` / `naming-and-symbolism.md` linked
`../LICENSE` (the code license — LGPL at the time, now Apache-2.0) as if it were the CC-BY-SA text.

*Action taken:* added [`LICENSE-DOCS.md`](../LICENSE-DOCS.md) (states the code/docs
split, references the canonical CC-BY-SA-4.0 text by URL rather than vendoring a
possibly-stale copy) and repointed the three broken links to it.

**License change (maintainer decision, applied):** the code license was switched
from LGPL-3.0 to **Apache-2.0** to better fit the institutional/ecosystem adoption
goal (permissive + an express patent grant; the same choice as Cosmos SDK, and
Creative Commons advises against CC for code in any case). This touched the
canonical `LICENSE` (now the Apache-2.0 text), all 125 SPDX headers, the
`pyproject.toml` classifier, the removal of the now-irrelevant `LICENSE.GPL`, a new
`NOTICE` file (Apache convention; reinforces attribution), and the LGPL-specific
prose throughout the docs/website/attribution guide (rewritten to Apache's
permissive semantics — no copyleft, §4 notice-retention, patent grant). The
documentation remains **CC-BY-SA-4.0**; the code/docs split architecture is unchanged.

### L3 — Marketing register vs disclaimer register · **[FIXED — partial]**

The README used stronger compliance language ("MiCA-compliant STO templates")
than the disclaimer's careful "informational, not a compliance assurance."

*Action taken:* the README intro now states the correct regime and points to the
corrected doc, and the same correction was applied to
`docs/setup-heimdall-operator.md`, `docs/v11rc-changes.md`, and the website
(`kern_site/index.html`, `kern_site/whitepaper.html`). No remaining text claims
the securities templates are MiCA instruments.

## Technical / security

### T1 — Skald recursion → consensus non-determinism · **[FIXED — code]**

Skald **allowed recursion** (via `internal` functions), contradicting the docs'
"no recursion" claim, and the type checker did not detect it. Deep recursion
terminated only by raising the host interpreter's `RecursionError`, whose
threshold **varies by machine, OS build, and Python version**. A contract that
recurses near that threshold could therefore **succeed on one validator and fail
on another → divergent state roots → consensus fork.** This is the most
important *code* finding.

*Action taken:* added `_check_no_recursion` to `kern/skald/typecheck.py` — it
builds the static call graph and rejects any cycle (direct or mutual) at deploy
time, with a clear error naming the cycle. Added 5 tests
(`tests/test_typecheck.py`). All 10 example contracts still type-check. The docs
(`skald-language.md`, `use-cases.md`) were updated from "bounded depth" to
"recursion statically rejected," which is now accurate and a stronger guarantee.

### T2 — L1 has no gas metering · **[FIXED — claim + optional mechanism shipped, off by default]**

"EVM Yellow Paper-compliant gas pricing" is true of the **rollup Mini-EVM only**.
At L1, `tx.gas_limit` is unused, `gas_used` is a flat constant or echoes the
limit, the fee is a flat sender-chosen `tx.fee`, and there is **no per-block gas
cap**. Because Skald has no loops and recursion is now forbidden, this is not a
node-killing DoS, but it does mean the L1 has no compute-proportional fee and no
economic spam bound.

*Action taken (claim):* the README now scopes gas metering to the rollup and
describes the L1's flat-fee / terminates-by-construction model honestly.

*Action taken (mechanism):* an **optional fee floor + per-block size cap** is now
implemented (`kern/chain.py`: `fee_params`, `tx_min_fee`, `check_fee_rules`, wired
into `validate_block`), **disabled by default**. Because it decides block validity
it is a consensus rule, so it is configured from chain state — at genesis or via the
protocol-governance whitelist — and never from a local flag (which would fork the
chain). Proposed defaults: `fee_floor_base = 100` mukrn, `fee_floor_per_byte = 2`
mukrn/byte, `max_block_bytes = 1 MiB`, calibrated so a legitimate transfer's floor
(~742 mukrn) stays under the current default fee while block-stuffing costs ≥ ~2.4
KRN/block. Documented in [`fee-floor.md`](fee-floor.md); 11 tests in
`tests/test_fee_floor.py` cover the pure rule, the `validate_block` gate (on and
off), and governance activation routing. When disabled (the default), behaviour is
byte-for-byte identical to prior releases, so all existing tests are unaffected.

*Still open:* a full demand-responsive base fee (EIP-1559-style) and per-opcode L1
compute metering remain future work; this is a floor + cap, not a dynamic gas market.

### T3 — `verify()` did not fail closed · **[FIXED]**

`crypto.verify()` caught only `BadSignatureError`; a malformed public key or
signature (wrong length) raised an uncaught `ValueError`/`TypeError`. Every
current caller already guards this and checks identity, so it was not
exploitable — but the primitive should be self-defending.

*Action taken:* `verify()` now also catches `ValueError`/`TypeError` and returns
`False` (defence in depth).

### T4 — `copy.deepcopy(state)` per transaction · **[FIXED — hot path; RECOMMENDED — full journaling]**

`apply_transaction` deep-copied the **entire** chain state on every
transaction — O(state size) per tx. Tracing every path showed a snapshot is
only actually needed where an op mutates and *then* can fail. In particular:
signature/nonce/fee checks happen before any mutation; `TRANSFER` debits via a
checked `_debit` that never leaves partial state; only `CALL` (which moves value
to the callee before running revertible contract logic) and the complex
governance/slashing/delegation/attestation ops genuinely need rollback.

*Action taken:* restructured `apply_transaction` so the snapshot is taken
**lazily** — never for bad-signature/bad-nonce/insufficient-fee spam, and never
on the `TRANSFER` hot path — and is taken **after** the fee debit + nonce bump so
rollback retains them without re-applying. State semantics are identical on every
path (verified by the full suite plus two new locking tests in
`tests/test_chain.py`: a failed transfer still charges the fee, and a reverting
value-bearing CALL rolls the value back while keeping the fee). Measured effect:
transfer cost is now ~flat regardless of state size (~0.43 ms/transfer at 100 vs
20 000 accounts), where the old per-tx deepcopy alone cost ~13 ms at 20 000
accounts — i.e. ~30× faster on a large state, widening as state grows.

*Still recommended:* a full journaled / copy-on-write state would also remove the
snapshot from the `CALL` and complex-op paths (the remaining O(state) cases). That
is a deliberate, designed change — a missed mutation site in a hand-rolled journal
is a silent consensus-corruption bug — and should be done with dedicated coverage,
not patched blind. It remains the top performance item for the road to mainnet.

## Consistency / data integrity

### C1 — Genesis distribution vs README · **[FIXED — table; RECOMMENDED — decision]**

The README advertised Foundation **15%**; the executable `genesis.json` allocates
Foundation **14M** plus **1M to a `bootstrap_baker`** not listed in the table
(totals reconcile to 100M). Also, the Foundation pool **shares an address with
the treasury** (commingling), and the bootstrap baker is the **sole genesis
validator** (single point of control at launch).

*Action taken:* the README table now matches `genesis.json` exactly and adds an
"Allocation notes (reconcile before genesis)" block flagging the
Foundation/treasury address split and the single-validator concern.
*Recommended:* decide the intended split, separate Foundation and treasury
addresses, and stage independent validators in early.

### C2 — Documentation drift · **[FIXED]**

`use-cases.md` referenced "planned in v0.2" rollups and "not part of v0.1"
privacy for features already shipped. Updated to reflect the current state and to
point at the implementing modules/docs.

## Use cases (assessment, no code change)

The targeting is coherent and the "not for" section is a strength. The honest
caveat: every named target — CBDC pilots, national land registries, verifiable
AI-inference markets — is a multi-year, hard-to-win institutional play, and
adoption (not capability) is the unsolved problem. The genuinely differentiated
wedge is **compliance-by-construction**, and it is *stronger* once pointed at the
correct regime (securities law, per L1) rather than MiCA. Leading with one
narrow, winnable beachhead would serve the project better than six broad
domains.

## Items still on the maintainer (require a decision, not a code fix)

- **T2 — an L1 fee floor / per-block work cap.** This changes consensus rules and
  needs chosen parameters; it is an economic-policy decision, not a mechanical
  fix, so it is documented rather than invented here.
- **C1 — separating the Foundation and treasury addresses, and staging
  independent validators.** Separating the addresses requires a *new keypair you
  control* (it should not be a key generated by a reviewer), so it is flagged in
  the README rather than silently changed in `genesis.json`.
- **Independent security audits and counsel review** — gating items that nothing
  in this review substitutes for.
